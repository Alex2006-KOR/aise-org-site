# aise-core를 한 쪽으로

::: lead
**책임은 정하고 판단은 맡기는, AI 에이전트 조직 거버넌스 프레임워크** — 지금까지는 aise-core를 이렇게
설명합니다(임시 정의).
:::

솔직히 말하면 저는 아직도 aise-core를 무엇이라고 불러야 할지 잘 모르겠습니다. 위 한 줄은 지금 제가 쓰는
설명일 뿐이고, 더 맞는 말을 찾으면 바꾸겠습니다. 아래는 이 사이트 전체를 한 쪽에 줄인 것입니다. 각 줄을
누르면 그 단계의 자세한 쪽으로 갑니다.

## 이야기 순서

::: point **[1. 배경](/story/background)** — Claude Code를 쓴 지 넉 달(2026년 10월 기준), 매번 같은 규칙을 설명하는 데 지쳐 프레임워크를 만들기 시작했습니다.
두 번의 시행착오(`aise-workflow`, `aise-development`)에서 네 가지 필요와 여섯 가지 문제를 얻었고, 마지막에는
"무엇을 AI에게 맡길까"에 "어떻게, 어디까지 통제할까"라는 질문이 더해졌습니다. → [배경](/story/background)
:::

::: point **[2. 한눈에 보기](/story/at-a-glance)** — 운영자는 참모하고만 이야기하고, 참모는 부서를 꾸리고, 부서의 PM이 일을 나눠 부서원에게 맡깁니다.
구조 그림 한 장, 이번 주에 실제로 있었던 요청 하나를 처음부터 끝까지, 그리고 누가 무엇을 하는지 표 하나로
보여 드립니다. → [한눈에 보기](/story/at-a-glance)
:::

::: point **[3. 왜 조직인가](/story/why-organization)** — 프롬프트로 세밀하게 통제하려다 실패했고, "무엇을 에이전트로 만들까"를 고민하는 것 자체가 낭비라고 느꼈습니다.
그래서 판단은 맡기고, 대신 결과가 원하는 방향으로 나오게 할 구조로 회사의 책임 분리를 빌려 왔습니다.
→ [왜: 통제와 조직 모델](/story/why-organization)
:::

::: point **[4. 원칙](/story/principles)** — 원칙과 경계는 먼저 정하고, 기능은 열어 둡니다. 중심축은 OCP와 SRP 두 개입니다.
나머지 SOLID 원칙, SSOT, 레이어드 패턴이 어떻게 들어갔는지는 의도한 것과 자연스럽게 맞아떨어진 것을
나눠서 적었습니다. → [왜: 원칙](/story/principles)
:::

::: point **[5. 어떻게 지키나](/story/how-it-is-kept)** — 글로 쓴 규칙은 어겨지므로, 꼭 지킬 것만 훅으로 강제하고 나머지는 실제로 일어난 일을 보고 정합니다.
감시 목록, 독립 재검증, 핸드오프, 토큰 모니터링, 그리고 그 과정의 실패들. → [어떻게 유지하나](/story/how-it-is-kept)
:::

::: point **[6. 배포와 여러 도구](/story/distribution)** — 배포하는 것은 조직이 아니라 정책·훅·도구입니다. 조직은 쓰는 사람이 자기 취향대로 꾸립니다.
여러 도구에서 쓰는 설계는 되어 있지만 Claude Code에서만 구현됐고, 다른 도구에서는 **검증 전**입니다.
→ [배포와 여러 도구](/story/distribution)
:::

::: point **[7. 성장·성과·한계](/story/growth-and-limits)** — 성장은 개별 역할이 아니라 포트폴리오와 공통 템플릿에 쌓입니다. 성과는 아직 **TBD**입니다.
프로젝트들이 진행 중이라 평가는 이르다고 판단했습니다. 아직 풀지 못한 것은 한계 절에 모았습니다.
→ [성장, 성과, 한계](/story/growth-and-limits)
:::

## 이 사이트를 읽는 법

::: point 모든 쪽은 세 단계입니다: 한 문장, 개조식 요점, 접혀 있는 상세.
발표하거나 빠르게 훑을 때는 요점만 보시면 됩니다. 요점을 누르면 그 뒤의 이유, 실제 사례, 근거 기록이
펼쳐집니다. 쪽 맨 위의 **모두 펼치기 / 모두 접기**로 한 번에 바꿀 수 있고, 인쇄하면 접힌 내용까지 모두
나옵니다.
:::

::: point 앞쪽은 이야기 트랙, 뒤쪽은 참고 자료입니다.
이야기 트랙(1–7)은 제가 겪은 순서대로 씁니다. 구조·모드·생명주기 같은 상세는 기존의 참고 자료 쪽들에 있고,
이야기 쪽에서 그곳으로 링크합니다. 예전 첫 화면은 [AISE 개요](/overview)로 옮겨 그대로 두었습니다.
:::

::: point 확인 정도를 표시합니다: 설계됨 · 구현됨 · 검증 전, 그리고 기록 있음 · 운영자 경험 · 가설.
아직 해 보지 않은 것은 해 본 것처럼 쓰지 않습니다. 근거가 기록으로 남아 있는지, 제 기억과 경험인지,
아직 가설인지도 구분합니다. 근거 기록이 있는 저장소(aise-core)는 지금 비공개이고 나중에 공개할 예정이라,
지금은 경로만 적고 링크는 걸지 않았습니다.
:::

::: point 어떤 회사의 이야기도 아닙니다.
제가 일하는 환경에서 겪은 일을 바탕으로 했지만, 특정 회사의 시스템이나 규칙은 쓰지 않고 "사내망에서만
쓸 수 있는 환경"처럼 일반화했습니다.
:::
