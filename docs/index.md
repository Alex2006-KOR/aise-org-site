# aise-core를 한 쪽으로

::: lead
**책임은 정하고 판단은 맡기는, AI 에이전트 조직 거버넌스 프레임워크** — 지금까지는 aise-core를 이렇게 설명한다(임시 정의).
:::

운영자는 aise-core를 무엇이라고 불러야 할지 아직 정하지 못했다. 위 한 줄은 지금의 설명이고, 더 맞는 말을 찾으면 바꾼다. 아래는
사이트 전체를 한 쪽에 줄인 것이다. 각 줄을 누르면 그 장으로 간다.

## 이야기 순서

::: point **[1. 왜 시작했나](/story/background)** — AI 에이전트로 여러 프로젝트를 함께 진행하면 비용은 빠르게 늘고 결과는 일정하지 않다.
두 번의 시도에서 네 가지 필요와 여섯 가지 문제가 나왔고, 질문은 "어떻게, 어디까지 통제할 것인가"로 모였다.
:::

::: point **[2. 해법: 회사의 구조를 빌린다](/story/at-a-glance)** — 행동 하나하나를 통제하는 대신 판단은 맡기고, 책임을 회사의 구조로 묶는다.
운영자는 참모하고만 이야기하고, 업무참모는 부서를 꾸리고, PM이 일을 나눠 부서원에게 맡긴 뒤 결과를 확인한다. 지시에서 보고까지를
다섯 문장과 실제 요청 하나로 보인다.
:::

::: point **[3. 원칙](/story/principles)** — 원칙과 경계는 먼저 정하고, 기능은 열어 둔다. 중심축은 SRP와 OCP다.
헌법의 다섯 원칙, 나머지 SOLID와 SSOT, 레이어드 아키텍처, AI라서 다르게 한 것, 흔한 방식과 갈리는 일곱 축.
:::

::: point **[4. 구조](/story/structure)** — 실행 책임은 운영자 — 부서 — 부서원의 두 단계, 참모는 그 밖에서 각자 한 가지 질문을 맡는다.
조직도와 실행 그래프, 참모 셋과 경영참모, 클래스인 역할, 프로젝트 하나인 부서, 두 모드, 템플릿과 인스턴스.
:::

::: point **[5. 어떻게 유지하나](/story/how-it-is-kept)** — 헌법이 원칙을, 거버넌스가 운영 정책을 정하고, 어댑터의 훅이 꼭 지킬 것만 강제한다.
정책이 요구사항을 거쳐 훅이 되는 과정, 훅의 구성, 글로 쓴 금지가 다음 날 어겨진 사건.
:::

::: point **[6. 운영](/story/operation)** — 운영자는 모드를 정하고 업무참모에게 말한다. 기억은 부서 기록 세 파일에 남는다.
부서가 꾸려지는 과정, 부서 안과 부서 사이의 위임, 매번 새로 시작하는 PM, 핸드오프, 멈춘 위임 깨우기.
:::

::: point **[7. 검증과 평가](/story/verification)** — 보고는 실제 산출물로, 화면은 실제 브라우저로 다시 확인한다.
조직 자체는 실제 기록으로 감사하고, 비용은 실행 그래프와 함께 본다. 실제 실행 그래프와 평가 산출물을 싣는다.
:::

::: point **[8. 배포와 여러 도구](/story/distribution)** — 배포하는 것은 조직이 아니라 정책·훅·도구다.
여러 도구에서 쓰는 설계는 돼 있지만 Claude Code에서만 구현됐고, 다른 도구에서는 **검증 전**이다.
:::

::: point **[9. 성장, 성과, 한계](/story/growth-and-limits)** — 성장은 개별 역할이 아니라 포트폴리오와 공통 템플릿에 쌓인다. 성과는 아직 **TBD**다.
프로젝트들이 진행 중이라 평가는 이르다. 아직 풀지 못한 것은 한계 절에 모았다.
:::

## 이 사이트를 읽는 법

::: point 모든 장은 세 단계다: 한 문장, 짧은 요점 제목과 설명, 접혀 있는 상세.
발표하거나 빠르게 훑을 때는 제목과 요점만 보면 된다. 상세를 누르면 배경, 문제, 해결 방법과 근거 기록이 펼쳐진다. 쪽 맨 위의 **모두
펼치기 / 모두 접기**로 한 번에 바꿀 수 있고, 인쇄하면 접힌 내용까지 모두 나온다.
:::

::: point 확인 정도를 표시한다: 설계됨 · 구현됨 · 검증 전, 그리고 기록 있음 · 운영자 경험 · 가설.
아직 해 보지 않은 것은 해 본 것처럼 쓰지 않는다. 근거가 기록으로 남아 있는지, 운영자의 경험인지, 아직 가설인지도 구분한다. 근거
기록이 있는 저장소(aise-core)는 지금 비공개이고 나중에 공개할 예정이라, 지금은 경로만 적고 링크는 걸지 않는다.
:::

::: point 어떤 회사의 이야기도 아니다.
운영자가 일하는 환경에서 겪은 일을 바탕으로 했지만, 특정 회사의 시스템이나 규칙은 쓰지 않고 "사내망 전용 환경"처럼 일반화했다.
:::
