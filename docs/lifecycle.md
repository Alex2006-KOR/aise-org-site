# 같은 문제를 두 번 처음부터 풀지 않으려면

[Philosophy](/philosophy)의 셋째 원칙 "조직은 지속적으로 성장해야 한다"가 실제로 어떻게 돌아가는지는,
여섯 단계를 한 바퀴 도는 순환으로 나타납니다.

## 여섯 단계

1. **채용(Recruitment)** — 필요한 역량이 없으면 새 역할을 만듭니다. 다만 만들기 쉽다는 이유로
   아무렇게나 늘리지 않습니다 — 기존 역할로 흡수할 수 있는지 먼저 확인하고,
   [뎁스-2 피라미드](/organization-model)를 벗어나지 않는지, 사유가 구체적인지 확인합니다.
2. **책임 부여(Assignment)** — 새 역할에게 역할과 책임을 명확히 부여합니다.
3. **협업(Collaboration)** — 업무 수행을 위해 실행 그래프를 구성합니다. 필요한 역할은 자유롭게
   협업합니다.
4. **보고(Reporting)** — 모든 업무 결과는 책임자에게 보고됩니다. 보고 체계는 조직도를 그대로
   따릅니다.
5. **피드백(Feedback)** — 리뷰와 피드백은 조직의 학습 과정이며, 다음 업무 방식과 지식자산에
   반영됩니다.
6. **지식자산화(Knowledge Accumulation)** — 새로 얻은 경험은 Workflow / Capability / Framework /
   Portfolio 같은 지식자산으로 쌓입니다. 그래야 다음에 비슷한 문제를 만난 다른 부서가 처음부터
   다시 풀지 않을 수 있습니다.

여섯 번째 단계는 다시 첫 번째로 이어집니다 — 쌓인 지식은 다음 채용 판단(기존 역할로 흡수할 수
있는가)의 근거가 되기 때문입니다.

## 부서 하나의 생애

이 여섯 단계는 조직 전체가 계속 도는 순환이고, 그 순환 안에서 부서(project) 하나하나는 각자의
생애를 따로 가집니다 — `draft → active → ended → closed`.

- **draft** — 요청이 아직 불분명할 때, 가볍게 대화하며 다듬는 단계입니다.
- **active** — 사용자가 명확히 승인하면, 실제 위임이 시작됩니다.
- **ended** — 사용자가 완료를 지시하면 이 단계로 넘어갑니다.
- **closed** — 지식누적 리뷰(회고 작성, 재사용 가능성 검토)까지 끝나야 완전히 닫힙니다.
