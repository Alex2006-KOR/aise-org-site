# 사이트 재작성 — 장 계획과 배치 표

operator의 내용 지시(2026-10-21, `directive.md` "operator content brief — site rewrite")를 사이트 전체에 적용하기 위한
계획이다. 1단계에서는 이 계획과 시범 두 장(1장, 5장)만 만든다. 2단계는 operator가 이 문서와 시범 장을 검토한 뒤에 한다.

**operator가 먼저 읽을 곳:** §2(장 구성) → 시범 장 두 개(`/story/background`, `/story/how-it-is-kept`) → §6(어디에도 맞지
않는 것 — operator가 정할 것) → §1(글쓰기 규칙, 시범 장에서 고칠 점이 있으면).

## 1. 글쓰기 규칙 (시범 장에 적용한 그대로)

| # | 규칙 | 시범 장에서의 모양 |
|---|---|---|
| W-1 | 객관적인 기술서 문체(한다체). 1인칭 없음. 짧은 문장. 제목이 말한 것을 본문에서 되풀이하지 않는다. | 주어는 "운영자", "PM", "aise-core" 또는 생략. "저", "제가" 없음. OD-10(이야기 트랙 1인칭)을 뒤집는다. |
| W-2 | 제목은 짧고 요점을 담는다. 접었을 때 슬라이드처럼 읽힌다. 독자가 아직 모르는 이름(`aise-workflow` 등)은 제목에 넣지 않고 본문에서 "…라는 이름이었다"로만 쓴다. | 1장 제목 "첫 번째 시도: 시스템 프롬프트를 만드는 프레임워크". |
| W-3 | 본문은 짧은 설명이 먼저. 쓸모 있는 곳에만 상세를 **배경 → 문제 → 해결 방법**으로 쓴다. 문제가 없는 주제는 다른 소제목을 쓴다. | 상세는 굵은 라벨 **배경.** / **문제.** / **해결 방법.**(1장 끝은 "해결 방향") — 기존 "결정 되짚어보기" 상자의 문제/조사/해결/강점과 같은 계열. |
| W-4 | 상세가 충분히 길 때만 접는다. 한두 문장은 접지 않는다. | 접힘은 `::: point 자세히 — …`. 짧은 설명은 절 본문에 바로 쓴다. |

| W-6 | operator의 설명(part N)은 재료이지 옮겨 적을 글이 아니다. 시기·경력 표현("첫 달", "넉 달")은 쓰지 않는다. 사건의 날짜는 기록의 사실일 때만 쓴다. | 1장에서 "Claude Code를 쓴 지 넉 달" 삭제. |
| W-7 | 흐름은 *Clean Architecture* 1장처럼: 겪은 문제 → 해법 → 원칙 → 구조 → 메커니즘 → 운영 → 한계. | §2의 장 구성. |
| W-8 | 근거 표기(OD-11)는 모든 쪽: 절 끝 `<Cite>`, 쪽 끝 `<SourceTable/>`. | 1장(운영자 경험 7건), 5장(규칙·결정·평가·기록·경험 27건). |
| W-9 | 기존 규칙 유지: 3단계(lead 한 문장 / 절의 짧은 설명과 접힘 요약 / 접힌 상세), KOR/EN 동시(INV-5), 공개 사이트 규칙(N-06), 축자 인용(INV-1/INV-4). | 그대로. |
